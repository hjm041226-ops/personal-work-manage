# 前端对接契约 · 作品后台管理系统(管理端)

> 本文件由《整合接口契约》(`docs/整合接口契约.md`)拆分而来,仅面向**作品后台管理系统前端**;对接中若与整合契约冲突,以整合契约为准。
> 完整版与两份旧契约(《后端接口文档(个人作品网站)》《后端接口文档(后台管理系统)》)的关系见 `docs/整合接口契约.md`。本文档的路径、JSON 键名、错误码、code/message 均逐字摘自整合契约(其已与 Go 源码逐字核对),对接一律以本文档为准。

**一句话定位:** 本文档是作品后台管理系统(管理端)前端的对接依据——所有 api-request 的 baseURL 统一为 `http(s)://<host>/api/v1/admin`,除 `POST /auth/login` 外全部请求需携带 `Authorization: Bearer <JWT>`。

**共享数据背景:** 后台管理系统与公开展示站共用同一 Go 后端进程、同一张 `works` 表,**后台管理的数据就是公开站展示的数据**,后台的增删改会**即时**影响公开站(公开站仅展示 `status=published && published=true && 未软删` 的作品;后台删除后公开站立即不可见)。

> ⚠️ 千万别把后台请求发到 `/api/v1/works`(那是公开组的匿名读接口,写操作不存在、且语义完全不同)。

## 2. 通用约定(后台组适用)

### 2.1 鉴权与 token 生命周期

- 登录成功(见 A1):把 `data.token` 存入本地(localStorage 等),`data.user` 入 store。
- 后续**每个请求**(除 `POST /auth/login` 外)加请求头:`Authorization: Bearer <token>`(注意 `Bearer ` 前缀与空格)。
- 任何受保护接口 token **缺失/非法/过期**:

```json
HTTP/1.1 401 Unauthorized
{ "code": 401, "message": "未登录或登录已过期", "data": null }
```

- token 有效期(A1 的 `remember` 参数):`remember=true` → **30 天**;否则(缺省/`false`)→ **24 小时**。
- **前端使用说明:** 建议在公共 request 封装里拦截 HTTP 401(无论 message)→ 清理本地 token、跳登录页;退出登录 = 本地丢弃 token 并跳登录页即可(服务端 logout 为无状态实现,见 A3)。

### 2.2 统一响应包裹

所有业务接口统一包裹:

```json
{ "code": 0, "message": "ok", "data": { } }
```

| 字段 | 类型 | 说明 |
|---|---|---|
| code | int | 0 成功;非 0 为业务错误码 |
| message | string | 人类可读说明,中文,可原样提示用户 |
| data | object / array / null | 业务数据;失败时为 `null` |

### 2.3 错误语义(后台组:HTTP 状态码与 body code 一致)

| 场景 | HTTP | body code | 说明 / message 示例 |
|---|---|---|---|
| 成功 | 200 | 0 | message `ok` |
| 参数错误 / 校验失败 | 400 | 400 | `作品名称不能为空`、`邮箱与密码不能为空`、`状态不合法(可选值:published / draft / archived)` 等 |
| 未认证 / 凭证错误 / token 过期 | 401 | 401 | `未登录或登录已过期`、`账号或密码错误` |
| 无权限 | 403 | 403 | 源码常量预留,**当前无接口触发** |
| 资源不存在(作品) | 404 | 404 | `作品不存在` |
| 冲突 | 409 | 409 | 源码常量预留,**当前无接口触发** |
| 服务端错误 | 500 | 500 | `服务器开小差了,请稍后再试`、`文件存储未配置,请先配置对象存储环境变量` |

> **唯一例外:** 后台组**未知路径**由引擎级 NoRoute 兜底,返回 HTTP 404 + `code:40400` + `接口不存在`(使用公开组错误码)。请求体不是合法 JSON → HTTP 400 + `code:400`。

### 2.4 时间与日期

- `createdAt` / `updatedAt`:**RFC3339 / UTC**(如 `2026-09-03T10:30:00Z`)。
- `date`(作品完成日期):字符串 **`YYYY-MM-DD`**(如 `2024-06-01`),**可空**;为空时该键不返回(B2/B1 形状 omitempty),前端取值需兼容缺键。
- 日期展示注意:`date` 是纯日期字符串,不要当作时间戳格式化。

### 2.5 作品 ID

- 后端生成,格式 **`PRJ-xxxx` 序列号**(从 `PRJ-0001` 起递增补零;序号 ≥10000 自然扩位,如 `PRJ-10000`),DB 列为 `VARCHAR(20)`。
- **新建(B3)时不传 `id`**,由服务端生成并保证唯一;响应 `data` 中带回。
- 前端路由/编辑回显直接使用该值,如 `/works/PRJ-8821/edit`。

### 2.6 分页形状(page 风格,必返回分页)

```
GET /api/v1/admin/works?page=&pageSize=
data: { "items": [...], "page": 1, "pageSize": 10, "total": n, "categories": [...] }
```

- `page` 从 1 开始;`pageSize` 默认 10,正整数、不设上限;`categories` 为分类计数数组(label 已是中文)。

### 2.7 上传限制

| 接口 | 用途 | 大小上限 | 格式 | 表单字段名 |
|---|---|---|---|---|
| `POST /files/cover` | 作品封面 | **≤20MB** | 仅 **PNG / WEBP / JPG**(按图片真实内容解码校验,不只看扩展名) | `file` |
| `POST /files/avatar` | 头像 | **≤5MB** | 同上 | `file` |
| `POST /profile/avatar` | 换头像(D3) | 规则同 C2(≤5MB) | 同上 | `file` |

- 对象存储(S3 兼容)未配置时,上传接口返回 **HTTP 500 + code 500** 中文语义提示,前端应兜底提示「上传功能暂不可用」(见 C1/C2)。

### 2.8 CORS

- CORS 由后端统一配置,前端**无需自行处理**;但前端部署的跨域来源必须在后端白名单内(后端环境变量 `ALLOWED_ORIGINS` 逗号分隔,可配 `*` 全放行;未配置时默认放行 `http://127.0.0.1:5174`、`http://localhost:5174`)。
- 后端放行方法 `GET,POST,PUT,PATCH,DELETE,OPTIONS`;允许请求头 `Authorization,Content-Type`;预检 OPTIONS 直接返回 HTTP 204。

### 2.9 works 字段说明(后台视角,与公开站同表同源)

**后台 JSON 键全集(详情/B3/B4 出现;列表行只含精简子集,见 B1):**

| JSON 键 | 类型 | 说明 |
|---|---|---|
| id | string | 作品 ID `PRJ-xxxx`(后端生成) |
| title | string | 作品名称(必填,trim 后非空,≤200 字符) |
| sub | string(可空) | 列表副标题(如 `UI/UX 设计 · Smart Cockpit`) |
| category | string | 分类**枚举键**:`web / app / desktop / others`(必填;`other` 输入归一为 `others`) |
| categoryLabel | string(可空) | 中文展示分类(如 `建筑科技`),独立存储;公开站 `category` 键即此值 |
| date | string(可空) | 项目完成日期 `YYYY-MM-DD`,可空 |
| status | string | `draft` / `published` / `archived`(恒返回) |
| views | int | 浏览量,恒返回;**服务端维护,写接口不可改** |
| cover | string | 封面图 URL(与公开站 `image` 同源) |
| coverFile | string(可空) | 封面文件名(展示用) |
| coverMeta | string(可空) | 封面文件信息文案(如 `2.4 MB · 1920x1080 px`) |
| url | string(可空) | 作品链接(不含 https:// 前缀的展示值) |
| repo | string(可空) | 仓库链接(同上) |
| desc | string(可空) | **Markdown 正文**(编辑页富文本内容,对应 DB `desc_md` 列;公开站详情 `desc` 与之同源同内容) |
| badge | string(可空) | 公开站卡片角标(如 `空间 3D • WebGL`) |
| summary | string(可空) | 公开站一句话简介 |
| descIntro | string(可空) | 公开站详情引言(DB `desc` 列,公开站 JSON 对应键为 `intro`;与上面的 `desc` 区分) |
| overlayLabel | string(可空) | 公开站详情大图浮层标签 |
| stats | array(可空) | 公开站详情浮层指标数组,元素 `{label:string, value:string}` |
| sortOrder | int | 排序权重,升序;公开列表固定按 `sort_order ASC, created_at DESC` |
| tags | array(可空) | 技术栈/标签数组(后台模糊搜索范围) |
| published | bool | 公开展示开关(恒返回) |
| featured | bool | 首页焦点推荐开关 |
| createdAt / updatedAt | string | RFC3339 / UTC |

**易混字段说明(务必区分):**

- **`desc` ≠ `descIntro`:** 后台 JSON `desc` = **Markdown 正文**(DB `desc_md` 列),回填给编辑器的富文本/Markdown 编辑区;`descIntro` = 公开站详情引言(DB `desc` 列,纯文本),两者是不同字段、分开编辑。对应公开站 JSON:公开站 `desc`(= Markdown 正文)与后台 `desc` 同源同内容;公开站 `intro`(引言)对应后台 `descIntro`。
- **`category` ≠ `categoryLabel`:** `category` 是存储/过滤用**枚举键**(表单下拉选的值);`categoryLabel` 是**中文展示分类**,供公开站展示,可另行维护(不填则公开站 `category` 键不返回)。
- **`status` 语义:** 后台列表返回**全部未软删**(`deleted_at IS NULL`)的作品,含草稿(`draft`)、已发布(`published`)与(若被 PATCH 置为)`archived`;**仅经 DELETE 软删的行不再出现**(`archived` 未软删仍会列出)。
- **`published`** 是公开展示的独立开关(与 `status` 双控:公开站要求 `status=published` **且** `published=true`);后台「保存草稿」可置 `status=draft` 或 `published=false`,公开站立即不可见。
- **`views`** 由服务端计数逻辑维护,新建恒为 0,更新也不覆盖,前端不可写、编辑表单不要提交。
- 可选字段为空时**键不返回**(JSON omitempty),例如 `sub`/`url`/`repo`/`coverFile`/`coverMeta`/`categoryLabel`/`badge`/`summary`/`descIntro`/`overlayLabel` 为空字符串、`date` 为空、`tags`/`stats` 为空数组时,对应键不会出现在 JSON 中;前端取值需兼容缺键。`views` / `published` / `featured` / `status` / `category` 恒返回。

## 3. 接口详解

> 除 A1 外均需请求头 `Authorization: Bearer <token>`。任何受保护接口 token 缺失/非法/过期:HTTP 401 + `{ "code": 401, "message": "未登录或登录已过期", "data": null }`(下文不重复列出,统一以此为准)。

### A1. 管理员登录 `POST /api/v1/admin/auth/login`

免鉴权。`Content-Type: application/json`。

请求体:

```json
{ "email": "admin@atelier-studio.com", "password": "********", "remember": true }
```

- `remember=true` → token 有效期 **30 天**;否则 **24 小时**。

成功响应 `data`(含 token 与 user):

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "token": "<jwt>",
    "user": {
      "id": 1,
      "email": "admin@atelier-studio.com",
      "name": "Elena Vance",
      "title": "创意总监 / 设计师",
      "bio": "专注极致美学、数字产品交互与品牌视觉构建。",
      "website": "https://elenavance.design",
      "avatar": "https://…/avatar.png",
      "role": "admin"
    }
  }
}
```

失败示例:

```json
HTTP/1.1 400 Bad Request
{ "code": 400, "message": "邮箱与密码不能为空", "data": null }

HTTP/1.1 400 Bad Request
{ "code": 400, "message": "邮箱格式不正确", "data": null }

HTTP/1.1 401 Unauthorized
{ "code": 401, "message": "账号或密码错误", "data": null }
```

**前端使用说明:** 登录页调用;成功把 `token` 存本地、`user` 入 store;401 时提示 `账号或密码错误`;400 时提示具体 message。

### A2. 当前登录用户 `GET /api/v1/admin/auth/me`

`data` = user 对象(同 A1 的 `user`,**不含 token**;形状见 D1 示例)。用于顶栏头像/姓名展示。

### A3. 退出 `POST /api/v1/admin/auth/logout`

无状态实现(不做 token 黑名单)。成功:

```json
{ "code": 0, "message": "ok", "data": null }
```

**前端使用说明:** 退出 = 本地丢弃 token + 跳登录页即可;也可调用本接口后清本地。

### B1. 作品列表 `GET /api/v1/admin/works`

Query 参数:

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| page | int | 1 | 页码,≥1 |
| pageSize | int | 10 | 每页条数,正整数(不设上限) |
| category | string | all | `all` 或枚举 `web/app/desktop/others`(`other` 归一为 `others`) |
| keyword | string | 空 | 模糊匹配 `title` / `sub` / tags |
| status | string | 空=全部 | `published` 或 `draft`;传空则不过滤(任何非软删行,含 archived,均返回) |
| sortBy | string | date | `date / createdAt / updatedAt / views / title` |
| order | string | desc | `asc` 或 `desc` |

排序细节:`ORDER BY <col> <dir> NULLS LAST, id ASC`——默认 `date DESC NULLS LAST`。

成功响应 `data`(行字段 = 列表精简版,**不含** `desc/url/repo/coverFile/coverMeta`):

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "items": [
      {
        "id": "PRJ-0001",
        "title": "ArchiSpace:空间建筑与 3D Web 查看器",
        "category": "web",
        "date": "2024-06-01",
        "status": "published",
        "views": 0,
        "cover": "https://placehold.co/1920x1200/1f2937/f1f5f9?text=ArchiSpace",
        "tags": ["Next.js", "Three.js", "Tailwind CSS"],
        "createdAt": "2026-09-03T10:30:00Z",
        "updatedAt": "2026-09-03T10:30:00Z"
      }
    ],
    "page": 1,
    "pageSize": 10,
    "total": 4,
    "categories": [
      { "key": "web", "label": "网站", "count": 3 },
      { "key": "app", "label": "移动应用", "count": 1 },
      { "key": "desktop", "label": "桌面", "count": 0 },
      { "key": "others", "label": "其他", "count": 0 }
    ]
  }
}
```

- `categories` **恒含 4 个分类**,计数缺失补 0,`label` 为中文;**计数独立于 `keyword`/`status` 过滤**,统计的是全部未软删作品(与「分类角标忽略搜索条件」一致),不要因加了搜索/状态筛选就重算它。

参数非法 → HTTP 400 + code 400(消息示例):`参数不合法:page 必须为正整数`、`参数不合法:pageSize 必须为正整数`、`分类参数不合法(可选值:all / web / app / desktop / others)`、`状态参数不合法(可选值:published / draft)`、`keyword 长度不能超过 100`、`排序字段不合法(可选值:date / createdAt / updatedAt / views / title)`、`排序方向不合法(可选值:asc / desc)`。

**前端使用说明:** 作品管理页表格列映射——缩略图=`cover`;标题=`title`;副标题=`sub`(空则自行兜底);发布时间=`date`(YYYY-MM-DD,可空);状态=`status`(published→已发布/绿,draft→草稿/黄);浏览量=`views`(千分位);编辑跳 `/works/{id}/edit`。分类胶囊计数用 `data.categories`(`label` 已是中文);搜索框把关键字放 `keyword`;分类过滤放 `category`。

### B3. 新建作品 `POST /api/v1/admin/works`

请求体 = 后台字段 + 公开站扩展字段(全可选字段见下表;未知键被忽略,向后兼容)。`id` 无需传,由后端生成。

```json
{
```

### B4. 更新作品 `PUT /api/v1/admin/works/{id}`

请求体与 B3 完全一致(**全字段覆盖语义**:未传的可选字段按上表缺省值处理,如 `status` 缺省变回 `draft`、`date` 缺省被清空,请前端回填完整对象再提交)。`views` 同样不可写。

成功:`data` = 更新后完整作品(B2 形状)。失败:HTTP 400(校验,同 B3 消息)、HTTP 404(`作品不存在`)。

**前端使用说明:** 编辑页「保存修改」:先 GET B2 回显 → 用户改动 → PUT 提交完整对象;成功提示「修改已保存」返回列表。

### B5. 归档删除 `DELETE /api/v1/admin/works/{id}`

软删:置 `deleted_at=now()` 且 `status='archived'`;列表与公开站立即不再返回。

成功:

```json
{ "code": 0, "message": "ok", "data": { "id": "PRJ-0001", "deleted": true } }
```

失败:HTTP 404 + `{ "code": 404, "message": "作品不存在", "data": null }`。

**前端使用说明:** 行操作「删除」二次确认后调用,`data.deleted===true` 视为成功并刷新列表(公开站即时移除,无需额外操作)。

### B6. 状态切换 `PATCH /api/v1/admin/works/{id}/status`

请求体:

```json
{ "status": "published" }
```

`status` 允许 `published` / `draft` / `archived`。成功:

```json
{ "code": 0, "message": "ok", "data": { "id": "PRJ-0001", "status": "published" } }
```

失败:非法状态 → HTTP 400 + `状态不合法(可选值:published / draft / archived)`;不存在 → HTTP 404 + `作品不存在`。

**前端使用说明:** 管理页「发布/下架」快捷操作可调用;注意:切到 `archived` 只是状态标记,不是 B5 软删(仍会出现在后台列表);真正归档删除走 B5。

### C1 / C2. 文件上传 `POST /api/v1/admin/files/cover`、`/files/avatar`

`Content-Type: multipart/form-data`,表单字段名 **`file`**。

| 接口 | 用途 | 大小上限 | 返回键 |
|---|---|---|---|
| `/files/cover` | 作品封面 | ≤20MB | url/fileName/fileMeta/size/width/height |
| `/files/avatar` | 头像 | ≤5MB | 同上 |

格式:仅 **PNG / WEBP / JPG**(按图片真实内容解码校验,不只看扩展名)。成功:

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "url": "https://media.example.com/uploads/cover/2026/09/3f9a2c1b4d5e6f7a8b9c0d1e2f3a4b5c.webp",
    "fileName": "nova-cover-master.png",
    "fileMeta": "2.4 MB · 1920x1080 px",
    "size": 2516582,
    "width": 1920,
    "height": 1080
  }
}
```

- `url` = `STORAGE_PUBLIC_BASE_URL` + 对象键;对象键形如 `uploads/cover/YYYY/MM/<随机12字节hex>.<ext>`(cover)与 `uploads/avatar/YYYY/MM/…`(avatar),后端随机命名,**无需前端传文件名**。
- `fileMeta` 由后端拼好(`大小 · 宽x高 px`,大小按 1024 进制显示 MB/KB/B),前端原样展示;`size` 为字节数,`width/height` 为图片像素。

失败示例:

```json
HTTP/1.1 400 Bad Request
{ "code": 400, "message": "请上传 file 字段的图片文件", "data": null }

HTTP/1.1 400 Bad Request
{ "code": 400, "message": "仅支持 PNG / WEBP / JPG 图片", "data": null }

HTTP/1.1 400 Bad Request
{ "code": 400, "message": "文件过大,封面最大 20MB", "data": null }
```

> 头像(C2)超限 message 为 `文件过大,封面最大 5MB`(其余相同)。

对象存储未配置时:

```json
HTTP/1.1 500 Internal Server Error
{ "code": 500, "message": "文件存储未配置,请先配置对象存储环境变量", "data": null }
```

> 对象存储(S3 兼容)未配置时的具体文案为 `文件存储未配置,请设置 S3_BUCKET/S3_ACCESS_KEY/S3_SECRET_KEY/STORAGE_PUBLIC_BASE_URL 等环境变量`,前端应兜底提示「上传功能暂不可用」。

**前端使用说明:** CoverUpload / 头像选择器:选择本地文件 → POST 上传 → 拿 `url` 回填表单(`cover` + `coverFile` + `coverMeta`),图片直用 `url` 预览(需为公开可访问地址)。注意:C1/C2 只负责上传并返回 URL,**不会自动修改任何数据**;要更新作品封面请把返回 URL 放进 B3/B4 请求体,要更新管理员头像请走 D3(它会自动落库)。

## 4. 后台组错误码表

| code | 含义 | 实际 message 示例 | HTTP |
|---|---|---|---|
| 0 | 成功 | ok | 200 |
| 400 | 参数错误 / 校验失败 | `作品名称不能为空`;`邮箱与密码不能为空`;`状态不合法(可选值:published / draft / archived)`… | 400 |
| 401 | 未认证 / 凭证错误 / token 过期 | `未登录或登录已过期`;`账号或密码错误` | 401 |
| 403 | 无权限(源码常量预留,**当前无接口触发**) | — | 403 |
| 404 | 资源不存在(作品) | `作品不存在` | 404 |
| 409 | 冲突(源码常量预留,**当前无接口触发**) | — | 409 |
| 500 | 服务端错误 | `服务器开小差了,请稍后再试`;`文件存储未配置,请先配置对象存储环境变量` | 500 |

> **例外:** 后台组**未知路径**由引擎级 NoRoute 兜底,返回 HTTP 404 + `code:40400` + `接口不存在`(使用公开组错误码);请求体不是合法 JSON → HTTP 400 + `code:400`。

**前端拦截器建议(后台组):**

- HTTP 401(无论 message)→ 清理本地 token、跳登录页;
- `code !== 0` → toast 后端 `message`;
- 上传类接口返回 500 且 message 含「文件存储未配置」→ 提示上传功能暂不可用;
- 其余(code 与 HTTP 状态一致)直接展示 message 即可。

## 5. 与旧契约《后端接口文档(后台管理系统)》的主要差异提醒

| # | 主题 | 旧文档 | 现行为(= 整合契约,以本文档为准) |
|---|---|---|---|
| 1 | 路径前缀 | `/auth/login`、`/works`、`/files/cover`… | 后台全部挂在 **`/api/v1/admin`** 下,baseURL 必须指到 `/api/v1/admin` |
| 2 | `desc` / `descIntro` 键语义 | Markdown 正文 | 后台 **`desc` = Markdown 正文**(DB `desc_md`)、**`descIntro` = 公开站详情引言**(DB `desc` 列),两个字段分开编辑、勿混;公开站详情 `desc`(Markdown 正文,与后台 `desc` 同源同内容)、`intro`(引言,对应后台 `descIntro`)同理区分 |
| 3 | 封面相关键 | `cover` 等 | `cover` / `coverFile` / `coverMeta` 与公开站 `image` **同源**(同一 DB `cover`/`cover_file`/`cover_meta` 列) |
| 4 | 作品 ID | `PRJ-%04d` | 后端生成 **`PRJ-xxxx`**(PRJ-0001 起,≥10000 扩位);新建不传 `id`,响应里拿 |
| 5 | 分类枚举 | 枚举定义分散 | 统一枚举 **`web/app/desktop/others`**(`other` 输入归一为 `others`),非法报 400;`categoryLabel` 中文展示分类可另行维护 |
| 6 | 列表行字段 | 列表不含 desc/url/repo | **同旧文档**:列表行(B1)不含 `desc/url/repo`,也不含 `coverFile/coverMeta`,仅详情接口(B2)才有 |
| 7 | 登录有效期 | remember 建议 7–30 天 / 否则 2–24 小时 | 明确为 `remember=true` → **30 天**,否则 **24 小时** |
| 8 | 新建响应 HTTP | 建议 201 亦可 | **HTTP 200** + `data` = 完整作品 |
| 9 | 分类计数 label | 示例为枚举小写(web…) | B1 `categories[].label` 输出**中文**(网站/移动应用/桌面/其他),与 E1 字典一致,角标可直接展示 |

其余(错误语义、分页形状、上传限制、403/409 预留等)以本文档及《整合接口契约》为准。
