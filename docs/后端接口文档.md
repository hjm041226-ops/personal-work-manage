# ATELIER CMS 后端接口契约文档（面向 Go 后端开发）

> 项目：个人作品展示网站后台管理系统（Atelier Administrative Interface）
> 前端：`portfolio-cms-web`（Vue3 + ant-design-vue，一期为静态演示）
> 本文用于后端按前端期望的字段与语义开发 Go 接口；对接阶段只需把前端各 `api-request` 由 mock 换成真实请求。
> 版本：v0.1（随前端静态版对齐）

---

## 0. 文档目的与阅读顺序

1. 先看「通用约定」：响应包裹、鉴权、分页、时间、ID、文件限制、枚举。
2. 再看「数据模型」：表结构与 Go struct 对应。
3. 按「接口清单」逐个实现，响应 JSON 字段名必须与示例完全一致（前端按名取值）。

5. 「开放问题」里的事项建议开工前与前端/产品对齐一次。
6. 附 Go 落地建议（gin + GORM）。

## 1. 通用约定

### 1.1 地址与版本

- Base URL：`/api/v1`（推荐前端 dev 通过 Vite 代理 `/api` → 后端；生产走同域或网关）。
- 无真实上传时图片地址可为外链；接入后由后端返回可访问 URL（相对路径 `/static/...` 或对象存储直链）。

### 1.2 数据格式

- 请求/响应均 UTF-8 JSON。
- 日期：`YYYY-MM-DD`（作品「项目完成日期 / 发布时间」列）。
- 时间戳：ISO 8601 / RFC3339，如 `2024-03-15T10:00:00+08:00`（`created_at / updated_at`）。
- ID：**字符串**，作品形如 `PRJ-8821`（前端路由 `/works/:id/edit` 直接使用该值，后端负责生成并保证唯一，建议前缀 + 自增补零，如 `PRJ-%04d`）。

### 1.3 统一响应包裹

```
{
  "code": 0,          // 业务码：0 成功；非 0 失败（见 1.6 错误码表）
  "message": "ok",
  "data": { ... }     // 业务数据；无数据时可为 null
}
```

- 业务码与 HTTP 状态码并存：HTTP 表示传输层语义（200/400/401/403/404/500），`code` 表示业务结果。鉴权失败 HTTP 401。
- 分页/列表接口的 `data` 结构统一：

```
data: {
  "items": [...],          // 当前页数据
  "page": 1,              // 从 1 开始
  "pageSize": 10,
  "total": 24,            // 过滤后的总数（前端用于分页展示）
  "categories": [...]     // 可选：分类计数（分类胶囊角标用），见 GET /works
}
```

### 1.4 鉴权

- Header：`Authorization: Bearer <token>`（JWT）。
- `remember=true` 时令牌有效期建议 7~30 天，否则 2~24 小时（前端登录页有「记住登录状态」）。
- 受保护接口未带/令牌失效：HTTP 401 + `{ "code": 401, "message": "未登录或登录已过期" }`。
- 退出登录建议服务端支持（黑名单可选，一期允许前端丢弃 token 即可）。

### 1.5 文件上传限制（与前端校验一致）

| 用途 | 格式 | 大小 | 建议尺寸 |
|---|---|---|---|
| 作品封面 | PNG / WEBP / JPG | ≤ 20MB | 16:10（如 1920×1200） |
| 头像 | PNG / WEBP / JPG | ≤ 5MB | 正方形（≥ 200×200） |

- 封面/头像传参名统一 `file`（multipart/form-data）。
- 返回中应包含可直接 `<img src>` 使用的 `url`（相对路径或直链），以及用于展示的 `fileName`、`fileMeta`（如 `2.4 MB · 1920x1080 px`，格式建议 `大小 · 宽x高 px`）。

### 1.6 错误码（建议）

| code | 含义 |
|---|---|
| 0 | 成功 |
| 400 | 参数错误（message 给出具体原因） |
| 401 | 未认证 / token 过期 |
| 403 | 无权限 |
| 404 | 资源不存在（如作品、用户资料） |
| 409 | 冲突（如邮箱已存在、标签重复等） |
| 500 | 服务端错误 |

```
失败示例：
HTTP/1.1 400
{ "code": 400, "message": "作品名称不能为空", "data": null }
```

## 2. 数据模型（MySQL / GORM 草案）

### 2.1 users（含个人资料字段，单管理员场景可只存一行）

```sql
CREATE TABLE users (
  id            BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  email         VARCHAR(120) NOT NULL UNIQUE COMMENT '登录邮箱',
  password_hash VARCHAR(255) NOT NULL COMMENT 'bcrypt',
  name          VARCHAR(60)  NOT NULL DEFAULT '' COMMENT '姓名',
  title         VARCHAR(60)  NOT NULL DEFAULT '' COMMENT '头衔，如 创意总监 / 设计师',
  bio           VARCHAR(500) NOT NULL DEFAULT '' COMMENT '个人简介（≤200字）',
  website       VARCHAR(255) NOT NULL DEFAULT '' COMMENT '个人仓库/主页链接',
  avatar        VARCHAR(512) NOT NULL DEFAULT '' COMMENT '头像 URL',
  role          VARCHAR(20)  NOT NULL DEFAULT 'admin',
  created_at    DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at    DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

### 2.2 works

```sql
CREATE TABLE works (
  id          VARCHAR(20)  NOT NULL PRIMARY KEY COMMENT '如 PRJ-8821，后端生成',
  title       VARCHAR(200) NOT NULL COMMENT '作品名称',
  sub         VARCHAR(200) NOT NULL DEFAULT '' COMMENT '列表副标题，如 UI/UX 设计 · Smart Cockpit（后端可空，由前端拼接时留空）',
  category    VARCHAR(20)  NOT NULL DEFAULT 'others' COMMENT '列表过滤分类：web/app/desktop/others（与前端分类胶囊一致）',
  date        DATE NULL COMMENT '项目完成日期（列表列 发布时间）',
  status      VARCHAR(20)  NOT NULL DEFAULT 'draft' COMMENT 'published 已发布 / draft 草稿 / archived 已归档(软删)',
  views       INT UNSIGNED NOT NULL DEFAULT 0 COMMENT '浏览量',
  cover       VARCHAR(512) NOT NULL DEFAULT '' COMMENT '封面 URL',
  cover_file  VARCHAR(255) NOT NULL DEFAULT '' COMMENT '封面文件名（展示用）',
  cover_meta  VARCHAR(120) NOT NULL DEFAULT '' COMMENT '封面文件信息文案，如 2.4 MB · 1920x1080 px',
  url         VARCHAR(255) NOT NULL DEFAULT '' COMMENT '作品链接（不含 https:// 前缀的展示值）',
  repo        VARCHAR(255) NOT NULL DEFAULT '' COMMENT '仓库链接（同上）',
  desc_md     LONGTEXT NULL COMMENT '作品描述（Markdown 文本）',
  tags        JSON NULL COMMENT '标签数组，如 ["HMI Design","Automotive"]',
  published   TINYINT(1) NOT NULL DEFAULT 1 COMMENT '属性开关：公开展示状态',
  featured    TINYINT(1) NOT NULL DEFAULT 0 COMMENT '属性开关：首页焦点推荐',
  created_at  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  deleted_at  DATETIME NULL COMMENT '软删除（归档删除）',
  INDEX idx_category (category),
  INDEX idx_status (status),
  INDEX idx_date (date)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

> 说明：
> - 「归档删除」= 软删（`DELETE /works/{id}`），列表默认排除 `deleted_at IS NOT NULL`。
> - 浏览量 `views`：一期无统计埋点，后端可自增或维持默认，列表直接返回。
> - `sub` 前端列表直接展示；若数据库不落该字段，可约定后端按「类型名 + ' · ' + 首个标签」生成，或留空由前端兜底。**建议先落库可空**，见「开放问题」。
> - `date` 对应前端表单「项目完成日期」与列表「发布时间」列共用，后端返回 `YYYY-MM-DD`。

### 2.3 Go struct 建议（JSON tag 与前端字段一一对应）

```go
type Work struct {
	ID        string    `gorm:"primaryKey;size:20" json:"id"`
	Title     string    `json:"title"`
	Sub       string    `json:"sub"`
	Category  string    `json:"category"`                 // web|app|desktop|others
	Date      *string   `json:"date"`                     // YYYY-MM-DD
	Status    string    `json:"status"`                   // published|draft|archived
	Views     int       `json:"views"`
	Cover     string    `json:"cover"`
	CoverFile string    `json:"coverFile,omitempty"`
	CoverMeta string    `json:"coverMeta,omitempty"`
	URL       string    `json:"url,omitempty"`
	Repo      string    `json:"repo,omitempty"`
	Desc      string    `gorm:"column:desc_md" json:"desc,omitempty"`
	Tags      []string  `gorm:"serializer:json" json:"tags,omitempty"`
	Published bool      `json:"published"`
	Featured  bool      `json:"featured"`
	CreatedAt time.Time `json:"createdAt"`
	UpdatedAt time.Time `json:"updatedAt"`
}

type User struct {
	ID       uint64 `json:"id"`
	Email    string `json:"email"`
	Name     string `json:"name"`
	Title    string `json:"title"`
	Bio      string `json:"bio"`
	Website  string `json:"website"`
	Avatar   string `json:"avatar"`
	Role     string `json:"role"`
	Token    string `json:"token,omitempty"` // 登录接口返回
}

type Paged[T any] struct {
	Items      []T       `json:"items"`
	Page       int       `json:"page"`
	PageSize   int       `json:"pageSize"`
	Total      int64     `json:"total"`
	Categories []CatStat `json:"categories,omitempty"`
}

type CatStat struct {
	Key   string `json:"key"`
	Label string `json:"label"`
	Count int64  `json:"count"`
}
```

## 4. 接口详细定义

### A1 登录

```
POST /api/v1/auth/login
Content-Type: application/json
```

请求体（对应前端登录表单与 `payload`）：

```json
{
  "email": "admin@atelier-studio.com",
  "password": "********",
  "remember": true
}
```

校验：`email` 必填且为邮箱格式，`password` 必填。成功响应 `data`：

```json
{
  "token": "<jwt>",
  "user": {
    "id": 1,
    "email": "admin@atelier-studio.com",
    "name": "Elena Vance",
    "title": "创意总监 / 设计师",
    "bio": "专注极致美学、数字产品交互与品牌视觉构建。",
    "website": "https://elenavance.design",
    "avatar": "https://.../avatar.png",
    "role": "admin"
  }
}
```

失败：`400`（参数错误）/ `401`（邮箱或密码错误：`{ "code": 401, "message": "账号或密码错误" }`）。
> 前端演示静态数据可参考：Elena Vance / elena.vance@atelier-cms.io / 头像为 Google lh3 直链。

### A2 当前用户

```
GET /api/v1/auth/me
Authorization: Bearer <token>
```

`data` = A1 中的 `user` 对象（不含 token）。用于顶栏头像、姓名展示与后续权限判断。

### A3 退出（可选）

```
POST /api/v1/auth/logout
Authorization: Bearer <token>
```
`data: null`。一期前端退出为本地清 token + 跳登录页，不调用也可。

### B1 作品列表（作品管理页主接口）

```
GET /api/v1/works?page=1&pageSize=4&category=web&keyword=nova&status=published&sortBy=date&order=desc
```

Query 参数：

| 参数 | 类型 | 说明 |
|---|---|---|
| page | int | 默认 1（从 1 开始） |
| pageSize | int | 默认 10；**前端演示固定 4**（`works-manage/state` 的 `PAGE_SIZE`），建议后端不限制上限即可 |
| category | string | `all` 或 `web / app / desktop / others`；缺省 all |
| keyword | string | 模糊匹配 `title`、`sub`、`tags` |
| status | string | 可选：`published / draft`；缺省全部（列表不含 archived 软删） |
| sortBy / order | string | 可选，默认 `date desc`（发布时间倒序） |

`data`：

```json
{
  "items": [
    {
      "id": "PRJ-8821",
      "title": "Nova 智能车机视觉系统",
      "sub": "UI/UX 设计 · Smart Cockpit",
      "category": "desktop",
      "date": "2024-03-15",
      "status": "published",
      "views": 1420,
      "cover": "https://.../cover/nova.webp",
      "tags": ["HMI Design", "Automotive", "UI/UX"],
      "createdAt": "2024-03-15T10:00:00+08:00",
      "updatedAt": "2024-03-15T10:00:00+08:00"
    }
  ],
  "page": 1,
  "pageSize": 4,
  "total": 24,
  "categories": [
    { "key": "web", "label": "web", "count": 8 },
    { "key": "app", "label": "app", "count": 7 },
    { "key": "desktop", "label": "desktop", "count": 5 },
    { "key": "others", "label": "others", "count": 4 }
  ]
}
```

前端用法：
- 表格列：缩略图=`cover`；标题=`title`；副标题=`sub`；发布时间=`date`；状态=`status`（published→已发布/绿，draft→草稿/黄）；浏览量=`views`；操作列编辑跳 `/works/{id}/edit`。
- 搜索框搜索 `title / sub / tags`；分类胶囊切换 `category`，角标计数来自 `categories`。
- 列表页建议后端返回每行**不含** `desc / url / repo`（省流量），详情接口再返回。

  "category": "desktop",
  "date": "2024-03-15",
  "status": "published",
  "views": 1420,
  "cover": "https://.../nova-cover-master.png",
  "coverFile": "nova-cover-master.png",
  "coverMeta": "2.4 MB · 1920x1080 px",
  "url": "nova-hmi.atelier.io",
  "repo": "github.com/atelier-studio/nova-hmi",
  "desc": "## 项目背景与愿景\n...",

### B3 新建作品（上传页「发布作品」）

```
POST /api/v1/works
Authorization: Bearer <token>
Content-Type: application/json
```

请求体（对应 `WorkForm` 的 `payload.form`）：

```json
{
  "title": "SaaS 智能化数据分析中台体验重构",
  "category": "web",
  "date": "2024-06-01",
  "url": "atelier.design/cases/analytics-hub",
  "repo": "github.com/your-repo/project",
  "desc": "撰写该项目的思考过程、核心问题解决策略...",
  "tags": ["Data Visualization", "SaaS"],
  "published": true,
  "featured": false,
  "cover": "https://.../cover/xxx.webp",
  "coverFile": "xxx.webp",
  "coverMeta": "2.1 MB · 1920x1200 px",
  "status": "published"
}
```

- `id` 由后端生成（`PRJ-xxxx`），请求无需传（前端上传页展示的 `#PRJ-8822` 仅为演示占位）。
- `status`：前端「发布作品」→ `published`；「保存草稿」→ 也可调用本接口置 `draft`（或单独草稿保存语义，建议统一：POST 带 `status`）。
- 后端建议校验：`title`、`category` 必填。
- 响应：`data` = 创建后的完整作品对象（HTTP 201 亦可）。
- `cover` 常见两种对接：①先调 `C1` 上传拿 URL 再提交；②后端允许 multipart 里携带封面文件与表单字段一起（`file` + JSON 字段混编）。推荐 ①，前端二期按 ① 实现。

### B4 更新作品（编辑页「保存修改」）

```
PUT /api/v1/works/{id}
Authorization: Bearer <token>
Content-Type: application/json
```

请求体 = B3 请求体（全部字段覆盖语义）。响应 `data` = 更新后完整作品。
校验失败 400；不存在 404。成功前端提示「修改已保存」并返回列表。

### B5 归档删除（作品管理行操作「删除」）

```
DELETE /api/v1/works/{id}
Authorization: Bearer <token>
```

实现为软删（置 `deleted_at` / `status=archived`），列表不再返回。
成功响应：

```json
{ "code": 0, "message": "ok", "data": { "id": "PRJ-8821", "deleted": true } }
```

404：作品不存在。

### B6 状态切换（可选）

```
PATCH /api/v1/works/{id}/status
Body: { "status": "published" | "draft" | "archived" }
```

### C1 / C2 文件上传

```
POST /api/v1/files/cover          # 或 POST /api/v1/files 带 type=cover
POST /api/v1/files/avatar
Content-Type: multipart/form-data; field: file
Authorization: Bearer <token>
```

成功 `data`：

```json
{
  "url": "/static/uploads/2024/06/nova-cover-master.png",
  "fileName": "nova-cover-master.png",
  "fileMeta": "2.4 MB · 1920x1080 px",
  "size": 2516582,
  "width": 1920,
  "height": 1080
}
```

- 建议后端限制格式/大小（表 1.5），超限返回 400 与具体 message（前端已有同规则校验文案：仅支持 PNG/WEBP/JPG、≤20MB 等）。
- 图片静态访问：`/static/...` 由 Go 直接托管或对象存储直链；务必支持跨域（前端 dev 在 5173 端口）。
- `width/height` 解析（封面比例 16:10 建议、头像方形建议），返回 `fileMeta` 文案可后端拼好，前端原样展示。

func (h *Handler) ListWorks(c *gin.Context) {
	var q struct {
		Page     int    `form:"page" default:"1"`
		PageSize int    `form:"pageSize" default:"10"`
		Category string `form:"category"`
		Keyword  string `form:"keyword"`
		Status   string `form:"status"`
	}
	_ = c.ShouldBindQuery(&q)

	db := h.db.Model(&model.Work{}).Where("deleted_at IS NULL")
	if q.Category != "" && q.Category != "all" {
		db = db.Where("category = ?", q.Category)
	}
	if q.Keyword != "" {
		like := "%" + q.Keyword + "%"
		db = db.Where("title LIKE ? OR sub LIKE ? OR JSON_CONTAINS(tags, ?)", like, like, `"`+q.Keyword+`"`)
	}
	if q.Status != "" {
		db = db.Where("status = ?", q.Status)
	}

	var total int64
	db.Count(&total)

	var items []model.Work
	db.Order("date DESC").Offset((q.Page - 1) * q.PageSize).Limit(q.PageSize).Find(&items)

	// categories 计数（忽略 keyword，与 demo 行为一致）
	type row struct{ Key string; Count int64 }
	var rows []row
	h.db.Model(&model.Work{}).
		Select("category as key, count(*) as count").
		Where("deleted_at IS NULL").
		Group("category").Scan(&rows)

	c.JSON(200, OK(Paged[model.Work]{
		Items: items, Page: q.Page, PageSize: q.PageSize, Total: total,
		Categories: rows,
	}))
}

// 登录示意（bcrypt + JWT）
func (h *Handler) Login(c *gin.Context) {
	var req struct {
		Email    string `json:"email" binding:"required,email"`
		Password string `json:"password" binding:"required"`
		Remember bool   `json:"remember"`
	}
	if err := c.ShouldBindJSON(&req); err != nil {
		c.JSON(400, Fail(400, "参数错误"))
		return
	}
	var u model.User
	if err := h.db.Where("email = ?", req.Email).First(&u).Error; err != nil ||
		bcrypt.CompareHashAndPassword([]byte(u.PasswordHash), []byte(req.Password)) != nil {
		c.JSON(401, Fail(401, "账号或密码错误"))
		return
	}
	ttl := time.Hour * 24
	if req.Remember {
		ttl = time.Hour * 24 * 30
	}
	token, _ := h.jwt.Sign(u.ID, ttl)
	c.JSON(200, OK(gin.H{"token": token, "user": u}))
}
