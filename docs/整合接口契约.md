# 个人作品站 + 后台管理系统 · 整合版接口契约(以 Go 后端实现为准)

> 本文档是《后端接口文档(个人作品网站)》(下称 **文档1 / 公开站**)与《后端接口文档(后台管理系统)》(下称 **文档2 / 后台**)两份原始契约的**整合版**,面向**两套前端**对接同一个 Go 后端(`D:\personal-work-backend`,一个后端进程、一张统一 `works` 表,公开站与后台共用同一份作品数据,后台增删改即时影响公开站)。
> **后台前端 baseURL 需指到 `/api/v1/admin`**(除 `POST /auth/login` 外全部接口需携带 `Authorization: Bearer <JWT>`);公开站前端 baseURL 指到 `/api/v1`(匿名)。
> 本文所有路径、JSON 键名、错误码、状态码均以 Go 源码逐字核对为准(路由:`internal/httpapi/router.go`、`public/handler.go`、`admin/handler.go`;JSON 形状:`internal/httpapi/dto/*.go`、`response/response.go`),**不以原始文档的示意为准**。

---

## 1. 通用约定

### 1.1 路径隔离与鉴权总览

一个 Go 服务同时挂载两组接口,路径前缀天然隔离:

| 组 | 前缀 | 鉴权 | 错误语义 |
|---|---|---|---|
| 公开站(文档1 契约) | `/api/v1` | 匿名,无需登录 | 业务失败 HTTP 200 + 5 位业务码 |
| 后台(文档2 契约) | `/api/v1/admin` | 除 `POST /auth/login` 外,均要求 `Authorization: Bearer <JWT>` | HTTP 状态码与 `code` 一致 |

> ⚠️ 后台前端全部业务请求的 baseURL 必须是 `/api/v1/admin`,而不是 `/api/v1`;否则会落到公开组或 404。

服务根路径还提供健康检查 `GET /healthz`(不属于任何一组,无需鉴权)。

### 1.2 数据格式与时间

- 请求/响应一律 UTF-8 JSON(`application/json; charset=utf-8`);上传类接口为 `multipart/form-data`,字段名 `file`。
- 时间戳:一律 **RFC3339 / UTC**(如 `2024-06-01T10:30:00Z`),对应 JSON 键 `createdAt` / `updatedAt`。
- 日期(作品完成日期):字符串 `YYYY-MM-DD`,JSON 键 `date`,**可空**(无值时该键不返回或为 null,见各接口)。
- JSON 键均为 camelCase;两套前端对同一作品看到的键名不同(见 §2 字段映射),**不要混用**。

### 1.3 统一响应包裹与错误语义(双轨)

所有业务接口统一包裹:

```json
{ "code": 0, "message": "ok", "data": { } }
```

| 字段 | 类型 | 说明 |
|---|---|---|
| code | int | 0 成功;非 0 为业务错误码 |
| message | string | 人类可读说明,中文,可原样提示用户 |
| data | object / array / null | 业务数据;失败时为 `null` |

**两组的失败语义不同(双轨),前端拦截器须按组区分处理:**

| 场景 | 公开组 `/api/v1`(文档1 语义) | 后台组 `/api/v1/admin`(文档2 语义) |
|---|---|---|
| 成功 | HTTP 200,`code:0`,message `ok`(个别接口携带中文 message,如联系表单) | HTTP 200,`code:0`,message `ok` |
| 可预期业务失败(参数校验、作品不存在、限流等) | **HTTP 固定 200**,以 body `code` 区分(40001/40401 等) | HTTP 状态码与 body `code` 一致(400/401/404 等) |
| 请求体不是合法 JSON | HTTP 400 + `code:40000` | HTTP 400 + `code:400` |
| 未认证 / 令牌过期 | 无此场景(匿名) | HTTP 401 + `code:401`,`message:"未登录或登录已过期"` |
| 作品不存在 | HTTP 200 + `code:40401` | HTTP 404 + `code:404` |
| 未预期服务端错误 | HTTP 500 + `code:50000` | HTTP 500 + `code:500` |
| 未知路径(两组合用引擎级 NoRoute) | HTTP 404 + `code:40400`,`message:"接口不存在"` | 同左(**注意:** 后台组未知路径的 `code` 是 40400 而非 404,这是唯一例外) |

公开站示例(业务失败仍是 HTTP 200):

```json
HTTP/1.1 200 OK
{ "code": 40401, "message": "作品不存在：PRJ-0001", "data": null }
```

后台示例(HTTP 与 code 一致):

```json
HTTP/1.1 401 Unauthorized
{ "code": 401, "message": "未登录或登录已过期", "data": null }
```

### 1.4 作品 ID

- 后端生成,格式 **`PRJ-xxxx` 序列号**:从 `PRJ-0001` 起按 `work_id_seq` 递增补零;序号 ≥10000 时自然扩位(如 `PRJ-10000`),DB 列为 `VARCHAR(20)`。
- **客户端新建时不传 `id`**,由服务端生成并保证唯一;演示种子占位为 `PRJ-0001` ~ `PRJ-0004`。
- 前端路由/编辑回显直接使用该值,如 `/works/PRJ-8821/edit`、`/work/PRJ-0001`。

### 1.5 分类枚举与文案

统一分类枚举 **`web` / `app` / `desktop` / `others`**(合并两份文档;**文档1 预留值 `other` 输入时归一为 `others`**,存储一律为 `others`)。

| 分类 | 公开站文案(dict) | 后台文案(E1 / 列表角标) |
|---|---|---|
| web | Web | 网站 |
| app | App | 移动应用 |
| desktop | Desktop | 桌面 |
| others | Others | 其他 |

关键规则:

- DB 列 `category` 存**枚举键**(后台 JSON 键 `category` 输出枚举键,如 `desktop`)。
- 公开站展示用的**中文分类名**(如 `建筑科技`)独立存在 DB 列 `category_label`;公开站 JSON 键也命名为 `category`(输出中文),后台 JSON 键为 `categoryLabel`。
- 后台写入时 `category` 必填且必须是枚举键(`other` 会被归一为 `others`),非法值报 400。

### 1.6 分页:两套形状

**公开站(offset 风格,可选分页):**

```
GET /api/v1/works?limit=&offset=
data: { "list": [...], "total": n, "limit": n, "offset": n }
```

- `limit` 1–100(可选);**不传 limit 返回全部**,此时 `data.limit = 0`(0 表示未启用分页),`total` 为命中总数。

**后台(page 风格,必返回分页):**

```
GET /api/v1/admin/works?page=&pageSize=
data: { "items": [...], "page": 1, "pageSize": 10, "total": n, "categories": [...] }
```

- `page` 从 1 开始;`pageSize` 默认 10,正整数、不设上限;`categories` 为分类计数数组。

### 1.7 CORS

- 白名单来源通过环境变量 `ALLOWED_ORIGINS`(逗号分隔)配置;支持 `*` 全放行。
- 未配置时默认放行开发端口:`http://127.0.0.1:5173`、`http://localhost:5173`(公开站 dev)、`http://127.0.0.1:5174`、`http://localhost:5174`(后台 dev)。
- 放行方法 `GET,POST,PUT,PATCH,DELETE,OPTIONS`;允许请求头 `Authorization,Content-Type`;预检 OPTIONS 直接返回 HTTP 204;`Access-Control-Max-Age: 86400`。

## 2. 数据模型

### 2.1 统一 `works` 表(两份文档字段并集)

一张表同时服务两套前端。以下为 **DB 列 → 公开站 JSON 键 → 后台 JSON 键** 的权威映射(来源:`internal/database/migrations/0001_init.sql` + `internal/model/models.go` + `internal/httpapi/dto/*.go`):

| DB 列 | 类型(默认) | 公开站 JSON 键 | 后台 JSON 键 | 说明 |
|---|---|---|---|---|
| `id` | VARCHAR(20) PK | `id` | `id` | 后端生成 `PRJ-xxxx`,PRJ-0001 起、≥10000 扩位 |
| `title` | VARCHAR(200) NOT NULL | `title` | `title` | 作品名称(公开站详情大标题) |
| `badge` | VARCHAR(100) DEFAULT '' | `badge` | `badge` | 公开站首页卡片角标(如 `空间 3D • WebGL`) |
| `category` | VARCHAR(20) DEFAULT 'others' | —(列表按 `categoryKey` 过滤) | `category` | 分类**枚举键** `web/app/desktop/others`(other 归一为 others) |
| `category_label` | VARCHAR(100) DEFAULT '' | `category`(中文,如 `建筑科技`) | `categoryLabel` | 公开站展示分类中文名,独立存储 |
| `summary` | VARCHAR(500) DEFAULT '' | `summary` | `summary` | 公开站一句话简介(首页卡片描述) |
| `sub` | VARCHAR(200) DEFAULT '' | — | `sub` | 后台列表副标题(如 `UI/UX 设计 · Smart Cockpit`) |
| `date` | DATE NULL | — | `date` | 项目完成日期,后台 JSON `YYYY-MM-DD`,可空 |
| `status` | VARCHAR(20) DEFAULT 'draft' | —(隐式过滤 published) | `status` | `published` / `draft` / `archived`(DELETE 软删时自动置为 archived) |
| `views` | INT DEFAULT 0 | — | `views` | 浏览量,服务端维护,写接口不可改 |
| `cover` | VARCHAR(512) DEFAULT '' | **`image`** | `cover` | 封面图可访问 URL;**公开站键名为 `image`** |
| `cover_file` | VARCHAR(255) DEFAULT '' | — | `coverFile` | 封面文件名(展示用) |
| `cover_meta` | VARCHAR(120) DEFAULT '' | — | `coverMeta` | 封面文件信息文案(如 `2.4 MB · 1920x1080 px`) |
| `url` | VARCHAR(255) DEFAULT '' | — | `url` | 作品链接(不含 https:// 前缀的展示值) |
| `repo` | VARCHAR(255) DEFAULT '' | — | `repo` | 仓库链接(同上) |
| `desc` | TEXT DEFAULT '' | **`desc`** | `descIntro` | **公开站详情引言**(大图上方引言段落) |
| `desc_md` | TEXT DEFAULT '' | — | **`desc`** | **后台 Markdown 正文**(编辑页富文本内容) |
| `overlay_label` | VARCHAR(200) DEFAULT '' | `overlayLabel` | `overlayLabel` | 详情页大图浮层标签(如 `WEBGL 引擎运行中 — 60 FPS`) |
| `tags` | JSONB DEFAULT '[]' | `tags` | `tags` | 技术栈/标签数组(公开站首页、详情;后台模糊搜索范围) |
| `stats` | JSONB DEFAULT '[]' | `stats` | `stats` | 详情浮层运行指标数组,元素 `{label:string, value:string}` |
| `sort_order` | INT DEFAULT 0 | —(列表按 sort_order ASC) | `sortOrder` | 排序权重,升序;公开列表固定按 `sort_order ASC, created_at DESC` |
| `published` | BOOLEAN DEFAULT TRUE | —(隐式过滤 published=TRUE) | `published` | 属性开关:是否公开展示 |
| `featured` | BOOLEAN DEFAULT FALSE | — | `featured` | 属性开关:首页焦点推荐(当前未参与公开排序) |
| `created_at` | TIMESTAMPTZ DEFAULT now() | `createdAt` | `createdAt` | RFC3339/UTC |
| `updated_at` | TIMESTAMPTZ DEFAULT now() | `updatedAt` | `updatedAt` | RFC3339/UTC |
| `deleted_at` | TIMESTAMPTZ NULL | —(隐式排除) | — | 软删标记;`DELETE` 时置 now() 且 `status='archived'` |

**可见性规则(公开站):** 必须同时满足 `deleted_at IS NULL`、`status='published'`、`published=TRUE`(见 `model.VisibleOnPublicSite`)。公开站作品不存在/未发布一律返回 `code 40401`、`message:"作品不存在：{id}"`(详情页空态依赖此行为,勿改动)。

**后台列表规则:** 返回全部**未软删**(`deleted_at IS NULL`)的作品,含草稿(`draft`)、已发布(`published`)与(若被 PATCH 置为)`archived`;仅经 DELETE 软删的行不再出现。

### 2.2 `users` 表(简述)

单管理员场景通常只有一行。列:`id`(BIGSERIAL)、`email`(唯一)、`password_hash`(bcrypt)、`name`、`title`(头衔)、`bio`(简介 ≤200 字)、`website`、`avatar`(头像 URL)、`role`(默认 `admin`)、`created_at`、`updated_at`。对外 JSON 形状(登录/当前用户/个人资料共用,永不外泄 password_hash):

```json
{ "id": 1, "email": "admin@example.com", "name": "林晨", "title": "创意总监 / 设计师", "bio": "…", "website": "https://…", "avatar": "https://…", "role": "admin" }
```

### 2.3 `contact_messages` 表(简述)

公开站联系表单落库。列:`id`(BIGSERIAL)、`name`、`email`、`message`、`ip`、`user_agent`(入库排查用,不进接口响应)、`created_at`。对外仅返回 `{id, createdAt}`。

## 3. 接口总览

### 3.1 公开组(`/api/v1`,匿名)

| # | 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|---|
| H | GET | `/healthz` | 无 | 健康检查(引擎级,非 /api/v1) |

## 4. 公开组接口详解

### H. 健康检查

```
GET /healthz
```

成功响应:

```json
{ "code": 0, "message": "ok", "data": { "status": "ok" } }
```

### P1. 获取作品列表(GET /api/v1/works)

匿名。**只返回可见作品**(status=published 且 published=true 且未软删)。

Query 参数(全部可选):

| 参数 | 类型 | 说明 |
|---|---|---|
| `limit` | int | 1–100;不传返回全部(`data.limit=0` 表示未分页) |
| `offset` | int | ≥0,跳过条数(与 limit 配合) |
| `keyword` | string | ≤100 字符;模糊匹配 `title` / `summary` / tags |
| `categoryKey` | string | 分类枚举键过滤:`web / app / desktop / others`(与 P2 字典一致) |

成功响应(`code=0`;列表行字段见 §2.1 映射):

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "list": [
      {
        "id": "PRJ-0001",
        "badge": "空间 3D • WebGL",
        "title": "ArchiSpace:空间建筑与 3D Web 查看器",
        "summary": "专为学生设计工作室打造的交互式浏览器端 3D 建筑浏览器,用于实时审查空间布局。",
        "tags": ["Next.js", "Three.js", "Tailwind CSS"],
        "image": "https://placehold.co/1920x1200/1f2937/f1f5f9?text=ArchiSpace",
        "category": "建筑科技"
      }
    ],
    "total": 4,
    "limit": 0,
    "offset": 0
  }
}
```

- 排序固定:`sort_order ASC, created_at DESC`。
- 失败示例(业务失败 HTTP 200):

```json
HTTP/1.1 200 OK
{ "code": 40001, "message": "参数不合法:limit 必须为 1–100 的正整数", "data": null }
```

其他参数错误消息:`"参数不合法:offset 必须为非负整数"`、`"参数不合法:keyword 长度不能超过 100"`。

**前端使用说明:** 首页 `onMounted` 拉取列表渲染卡片;`category` 键即中文展示分类,可直接展示;标签展示用 `tags`;封面用 `image`(不要用 `cover`)。当前作品量少,建议不传分页参数,一次取全量。

### P4. 提交联系表单(POST /api/v1/contact/messages)

匿名。`Content-Type: application/json`。

请求体:

```json
{ "name": "张三", "email": "zhangsan@example.com", "message": "想咨询一下 ArchiSpace 的合作事宜" }
```

校验规则(源码 `service/contact.go`):

| 字段 | 规则 | 校验失败 message(HTTP 200 + code 40001) |
|---|---|---|
| name | trim 后 1–50 个字符 | `姓名长度需为 1–50 个字符` |
| email | 格式 `^[^@\s]+@[^@\s]+\.[^@\s]+$` | `请检查：邮箱格式不正确` |
| message | trim 后 1–2000 个字符 | `留言长度需为 1–2000 个字符` |

成功响应(`code=0`,自定义中文 message,`id` 为数字):

```json
{
  "code": 0,
  "message": "留言已收到,感谢联系",
```

### C1 / C2. 文件上传(POST /api/v1/admin/files/cover、/files/avatar)

`Content-Type: multipart/form-data`,表单字段名 **`file`**。

| 接口 | 用途 | 大小上限 | 返回键 |
|---|---|---|---|
| `/files/cover` | 作品封面 | ≤20MB | url/fileName/fileMeta/size/width/height |
| `/files/avatar` | 头像 | ≤5MB | 同上 |

格式:仅 **PNG / WEBP / JPG**(按图片真实内容解码校验,不只看扩展名)。成功:

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "url": "https://media.example.com/uploads/cover/2026/09/3f9a2c1b4d5e6f7a8b9c0d1e2f3a4b5c.webp",

    "fileMeta": "2.4 MB · 1920x1080 px",
    "size": 2516582,
    "width": 1920,
    "height": 1080
  }
}
```

- `url` = `STORAGE_PUBLIC_BASE_URL` + 对象键;对象键形如 `uploads/cover/YYYY/MM/<随机12字节hex>.<ext>`(cover)与 `uploads/avatar/YYYY/MM/…`(avatar),后端随机命名,**无需前端传文件名**。
- `fileMeta` 由后端拼好(`大小 · 宽x高 px`,大小按 1024 进制显示 MB/KB/B),前端原样展示;`size` 为字节数,`width/height` 为图片像素。

```json
HTTP/1.1 400 Bad Request

```

**前端使用说明:** CoverUpload / 头像选择器:选择本地文件 → POST 上传 → 拿 `url` 回填表单(`cover` + `coverFile` + `coverMeta`),图片直用 `url` 预览(需为公开可访问地址)。注意:C1/C2 只负责上传并返回 URL,**不会自动修改任何数据**;要更新作品封面请把返回 URL 放进 B3/B4 请求体,要更新管理员头像请走 D3(它会自动落库)。

### 6.1 公开组(5 位业务码;业务失败 HTTP 200)

| code | 含义 | 实际 message 示例 | HTTP |

### 6.2 后台组(HTTP 状态与 code 一致)

| code | 含义 | 实际 message 示例 | HTTP |

| 404 | 资源不存在(作品) | 作品不存在 | 404 |
| 409 | 冲突(源码常量预留,**当前无接口触发**) | — | 409 |
| 500 | 服务端错误 | 服务器开小差了,请稍后再试;文件存储未配置,请先配置对象存储环境变量 | 500 |

> 例外:后台组**未知路径**由引擎级 NoRoute 兜底,返回 HTTP 404 + `code:40400` + `接口不存在`(使用公开组错误码,见 §1.3)。

## 10. 后台前端接入指引

### 10.1 baseURL 指到 `/api/v1/admin` 的调用点

后台前端(如 `portfolio-cms-web`)所有 api-request 的 baseURL 统一为 **`http(s)://<host>/api/v1/admin`**,逐个调用点:

| 前端调用点 | 函数 | 实际接口 |
|---|---|---|
| 登录页 | `login(payload,{email,password,remember})` | `POST /api/v1/admin/auth/login` |
| 顶栏当前用户 | AppShell | `GET /api/v1/admin/auth/me` |
| 退出 | (本地清理可选) | `POST /api/v1/admin/auth/logout` |
| 作品管理列表 | `fetchWorks(payload)` | `GET /api/v1/admin/works` |
| 作品管理删除 | `deleteWork(payload,id)` | `DELETE /api/v1/admin/works/{id}` |
| 编辑页回显 | `fetchWork(payload,id)` | `GET /api/v1/admin/works/{id}` |
| 编辑页保存 | 预留 | `PUT /api/v1/admin/works/{id}` |
| 上传页新建 | `createWork(payload,data)` | `POST /api/v1/admin/works` |
| 上传组件 | CoverUpload | `POST /api/v1/admin/files/cover` |
| 头像选择 | chooseAvatar | `POST /api/v1/admin/files/avatar` 或 `POST /api/v1/admin/profile/avatar` |
| 个人资料 | `getProfile/updateProfile(payload,data)` | `GET/PUT /api/v1/admin/profile` |
| 分类字典(可选) | 表单分类下拉 / 列表角标 | `GET /api/v1/admin/meta/categories` |

> ⚠️ 千万别把后台请求发到 `/api/v1/works`(那是公开组的匿名读接口,写操作不存在、且语义完全不同)。

### 10.2 token 携带规则

- 登录成功:把 `data.token` 存入本地(localStorage 等),`data.user` 入 store。
- 后续**每个请求**(除 login 外)加请求头:`Authorization: Bearer <token>`(注意 `Bearer ` 前缀与空格)。
- 建议在公共 request 封装里拦截:
  - HTTP 401(无论 message)→ 清理本地 token、跳登录页;
  - `code !== 0` → toast 后端 `message`;
  - 上传类接口 500 且 message 含「文件存储未配置」→ 提示上传功能暂不可用。
- 退出登录:本地丢弃 token 并跳登录页即可(服务端 logout 为无状态实现)。

### 10.3 后台维护公开站内容的约定(同一张 works 表)

后台写操作(POST/PUT)的结果**即时影响公开站**:

- 公开站仅展示 `status=published && published=true && 未软删` 的作品;后台「保存草稿」(`status=draft` 或 `published=false`)后公开站立即不可见,发布后立即可见。
- 后台删除(B5)后公开站立即下架(40401 空态)。
- 想让公开站卡片/详情展示完整,请在后台把公开站扩展字段一并维护:`badge`(角标)、`summary`(一句话简介)、`categoryLabel`(展示中文分类,不填则公开站 `category` 键不返回)、`descIntro`(详情引言)、`overlayLabel`、`stats`、`sortOrder`(公开列表排序,升序优先)。
- 公开站封面用的是后台的 `cover` 字段(公开接口键名 `image`),只填后台字段即可。
